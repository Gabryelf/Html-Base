💼 БД vs СУБД

База данных

  • Упорядоченный набор данных
  • Физические файлы (.mdf / .ldf)
  • Содержит таблицы, индексы, представления

СУБД

  • Программное обеспечение
  • Управляет доступом, транзакциями
  • Обеспечивает целостность и безопасность
Пример: холодильник и еда

СУБД — это холодильник (управляет хранением). БД — это еда (сами данные). Холодильник хранит и выдает еду по запросу.

🔑 Реляционная модель

Отношение — таблица
Кортеж — строка
Атрибут — столбец
Первичный ключ (PK)

Уникальный идентификатор каждой строки. Не может быть NULL и дублироваться.

Внешний ключ (FK)

Ссылка на PK другой таблицы. Обеспечивает связи между сущностями.

📐 Нормализация

Устранение избыточности и аномалий. Три основные нормальные формы:

1НФ

Атомарность: каждое значение неделимо. Никаких списков в одной ячейке.

2НФ

Полная зависимость от первичного ключа. Удаление частичных зависимостей.

3НФ

Отсутствие транзитивных зависимостей. Неключевые атрибуты не зависят друг от друга.

Пример: разбиваем таблицу «Заказы» на «Клиенты», «Заказы», «Товары».

⚡ ACID

Свойства транзакций, гарантирующие надёжность.

Atomicity

Атомарность: транзакция выполняется полностью или не выполняется вовсе.

Consistency

Согласованность: транзакция переводит БД из одного целостного состояния в другое.

Isolation

Изоляция: параллельные транзакции не влияют друг на друга.

Durability

Долговечность: после фиксации данные сохраняются даже при сбое.

🗣️ SQL — язык структурированных запросов

DDL (CREATE, ALTER, DROP) DML (INSERT, UPDATE, DELETE) DQL (SELECT) DCL (GRANT, REVOKE)
Пример: SELECT с JOIN

SELECT c.Name, o.Total
FROM Customers c
JOIN Orders o ON c.Id = o.CustomerId
WHERE o.Total > 1000;
